# INC-1017: chat degradation

Severity: SEV-2
Service: chat
Detected: 2026-08-08 15:04 UTC
Author: on-call engineer for chat

## Summary

Shortly after a routine change reached production, a share of requests returned stale or empty results for the chat service.
Alerting paged the on-call engineer, who opened this incident and pulled in the owning team.

## Timeline

- 15:00 Change reached production.
- 15:04 First alert fired: a share of requests returned stale or empty results.
- 15:09 On-call acknowledged the page and opened an incident channel.
- 15:15 Dashboards confirmed the impact was limited to chat.
- 15:22 The owning team joined and began comparing the change against the previous state.
- 15:31 Mitigation started.
- 15:47 Metrics back within normal range; incident moved to monitoring.

## Root cause

An off-by-one error in the pagination code skipped the last page of results.
Nothing in pre-production exercised this path at production scale, so the problem only appeared under real traffic.

## Resolution

We did not roll back: the team patched the value in place and restarted the affected pods.

## Follow-ups

- Add an alert on the leading indicator so the next occurrence pages earlier.
- Extend the pre-production checklist for chat changes.
- Review the runbook entry for this failure mode.
