# INC-1014: media degradation

Severity: SEV-2
Service: media
Detected: 2026-05-18 12:04 UTC
Author: on-call engineer for media

## Summary

Shortly after a routine change reached production, the error rate rose to twelve percent of requests for the media service.
Alerting paged the on-call engineer, who opened this incident and pulled in the owning team.

## Timeline

- 12:00 Change reached production.
- 12:04 First alert fired: the error rate rose to twelve percent of requests.
- 12:09 On-call acknowledged the page and opened an incident channel.
- 12:15 Dashboards confirmed the impact was limited to media.
- 12:22 The owning team joined and began comparing the change against the previous state.
- 12:31 Mitigation started.
- 12:47 Metrics back within normal range; incident moved to monitoring.

## Root cause

A race in the new cache warmer let two workers write the same key with different values.
Nothing in pre-production exercised this path at production scale, so the problem only appeared under real traffic.

## Resolution

We did not roll back: the team patched the value in place and restarted the affected pods.

## Follow-ups

- Add an alert on the leading indicator so the next occurrence pages earlier.
- Extend the pre-production checklist for media changes.
- Review the runbook entry for this failure mode.
