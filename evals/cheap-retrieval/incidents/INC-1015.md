# INC-1015: gateway degradation

Severity: SEV-3
Service: gateway
Detected: 2026-06-23 13:04 UTC
Author: on-call engineer for gateway

## Summary

Shortly after a routine change reached production, health checks began flapping across the fleet for the gateway service.
Alerting paged the on-call engineer, who opened this incident and pulled in the owning team.

## Timeline

- 13:00 Change reached production.
- 13:04 First alert fired: health checks began flapping across the fleet.
- 13:09 On-call acknowledged the page and opened an incident channel.
- 13:15 Dashboards confirmed the impact was limited to gateway.
- 13:22 The owning team joined and began comparing the change against the previous state.
- 13:31 Mitigation started.
- 13:47 Metrics back within normal range; incident moved to monitoring.

## Root cause

A feature-flag change enabled the new cache path in every region at once instead of the canary region only.
Nothing in pre-production exercised this path at production scale, so the problem only appeared under real traffic.

## Resolution

The change was rolled back across all regions and the service recovered as soon as the rollback finished.

## Follow-ups

- Add an alert on the leading indicator so the next occurrence pages earlier.
- Extend the pre-production checklist for gateway changes.
- Review the runbook entry for this failure mode.
