# INC-1001: checkout degradation

Severity: SEV-1
Service: checkout
Detected: 2026-01-03 08:04 UTC
Author: on-call engineer for checkout

## Summary

Shortly after a routine change reached production, p99 latency climbed above four seconds for the checkout service.
Alerting paged the on-call engineer, who opened this incident and pulled in the owning team.

## Timeline

- 08:00 Change reached production.
- 08:04 First alert fired: p99 latency climbed above four seconds.
- 08:09 On-call acknowledged the page and opened an incident channel.
- 08:15 Dashboards confirmed the impact was limited to checkout.
- 08:22 The owning team joined and began comparing the change against the previous state.
- 08:31 Mitigation started.
- 08:47 Metrics back within normal range; incident moved to monitoring.

## Root cause

A refactor of the retry helper dropped the jitter calculation, so every client retried in lockstep.
Nothing in pre-production exercised this path at production scale, so the problem only appeared under real traffic.

## Resolution

We rolled the deploy back to the previous release, and error rates returned to baseline within minutes.

## Follow-ups

- Add an alert on the leading indicator so the next occurrence pages earlier.
- Extend the pre-production checklist for checkout changes.
- Review the runbook entry for this failure mode.
