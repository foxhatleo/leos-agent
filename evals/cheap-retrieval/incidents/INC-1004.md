# INC-1004: billing degradation

Severity: SEV-1
Service: billing
Detected: 2026-04-18 11:04 UTC
Author: on-call engineer for billing

## Summary

Shortly after a routine change reached production, queue depth grew faster than workers could drain it for the billing service.
Alerting paged the on-call engineer, who opened this incident and pulled in the owning team.

## Timeline

- 11:00 Change reached production.
- 11:04 First alert fired: queue depth grew faster than workers could drain it.
- 11:09 On-call acknowledged the page and opened an incident channel.
- 11:15 Dashboards confirmed the impact was limited to billing.
- 11:22 The owning team joined and began comparing the change against the previous state.
- 11:31 Mitigation started.
- 11:47 Metrics back within normal range; incident moved to monitoring.

## Root cause

The latest release removed a null check from the session middleware.
Nothing in pre-production exercised this path at production scale, so the problem only appeared under real traffic.

## Resolution

A rollback was considered but rejected because the release also carried a schema migration; we shipped a forward fix instead.

## Follow-ups

- Add an alert on the leading indicator so the next occurrence pages earlier.
- Extend the pre-production checklist for billing changes.
- Review the runbook entry for this failure mode.
