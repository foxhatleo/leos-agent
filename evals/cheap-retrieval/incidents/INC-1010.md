# INC-1010: shipping degradation

Severity: SEV-1
Service: shipping
Detected: 2026-01-23 08:04 UTC
Author: on-call engineer for shipping

## Summary

Shortly after a routine change reached production, queue depth grew faster than workers could drain it for the shipping service.
Alerting paged the on-call engineer, who opened this incident and pulled in the owning team.

## Timeline

- 08:00 Change reached production.
- 08:04 First alert fired: queue depth grew faster than workers could drain it.
- 08:09 On-call acknowledged the page and opened an incident channel.
- 08:15 Dashboards confirmed the impact was limited to shipping.
- 08:22 The owning team joined and began comparing the change against the previous state.
- 08:31 Mitigation started.
- 08:47 Metrics back within normal range; incident moved to monitoring.

## Root cause

An off-by-one error in the pagination code skipped the last page of results.
Nothing in pre-production exercised this path at production scale, so the problem only appeared under real traffic.

## Resolution

A rollback was considered but rejected because the release also carried a schema migration; we shipped a forward fix instead.

## Follow-ups

- Add an alert on the leading indicator so the next occurrence pages earlier.
- Extend the pre-production checklist for shipping changes.
- Review the runbook entry for this failure mode.
