# INC-1018: sessions degradation

Severity: SEV-3
Service: sessions
Detected: 2026-09-13 16:04 UTC
Author: on-call engineer for sessions

## Summary

Shortly after a routine change reached production, login attempts started timing out for the sessions service.
Alerting paged the on-call engineer, who opened this incident and pulled in the owning team.

## Timeline

- 16:00 Change reached production.
- 16:04 First alert fired: login attempts started timing out.
- 16:09 On-call acknowledged the page and opened an incident channel.
- 16:15 Dashboards confirmed the impact was limited to sessions.
- 16:22 The owning team joined and began comparing the change against the previous state.
- 16:31 Mitigation started.
- 16:47 Metrics back within normal range; incident moved to monitoring.

## Root cause

The latest release removed a null check from the session middleware.
Nothing in pre-production exercised this path at production scale, so the problem only appeared under real traffic.

## Resolution

The change was rolled back across all regions and the service recovered as soon as the rollback finished.

## Follow-ups

- Add an alert on the leading indicator so the next occurrence pages earlier.
- Extend the pre-production checklist for sessions changes.
- Review the runbook entry for this failure mode.
