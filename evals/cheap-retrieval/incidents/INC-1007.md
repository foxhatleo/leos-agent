# INC-1007: payments-gateway degradation

Severity: SEV-1
Service: payments-gateway
Detected: 2026-07-08 14:04 UTC
Author: on-call engineer for payments-gateway

## Summary

Shortly after a routine change reached production, p99 latency climbed above four seconds for the payments-gateway service.
Alerting paged the on-call engineer, who opened this incident and pulled in the owning team.

## Timeline

- 14:00 Change reached production.
- 14:04 First alert fired: p99 latency climbed above four seconds.
- 14:09 On-call acknowledged the page and opened an incident channel.
- 14:15 Dashboards confirmed the impact was limited to payments-gateway.
- 14:22 The owning team joined and began comparing the change against the previous state.
- 14:31 Mitigation started.
- 14:47 Metrics back within normal range; incident moved to monitoring.

## Root cause

A race in the new cache warmer let two workers write the same key with different values.
Nothing in pre-production exercised this path at production scale, so the problem only appeared under real traffic.

## Resolution

A rollback was considered but rejected because the release also carried a schema migration; we shipped a forward fix instead.

## Follow-ups

- Add an alert on the leading indicator so the next occurrence pages earlier.
- Extend the pre-production checklist for payments-gateway changes.
- Review the runbook entry for this failure mode.
